## 1. 开发顺序与里程碑

**依赖顺序：Q1–Q6 已确认 → 授权/单本下载及后台/续传 PoC → 工程与协议基线 → 下载持久化 → UI 全链路 → 真机/APK 内测。**

下面按一名熟悉 Android 的开发者、设计/测试可及时评审估算；不含平台接入审批、未知协议变更、内置阅读器和复杂 PDF 编辑。区间仅供排期，不是交付承诺。原基础范围约 30–45 人日；已确认首版包含可靠 Range 续传/暂停，增加约 3–5 人日，当前粗估合计 **33–50 人日**。以下阶段区间与该工作量对应；人日不等于自然日或交付承诺，实际工期需结合并行度、人员投入与 PoC 结果重估。可选 PDF 写目录约另 3–7 人日，不计入首版；正式商店合规另估。

| 阶段 | 参考工作量 | 交付物 | 完成门槛 |
|---|---|---|---|
| M0 需求与技术验证 | 3–5 人日 | Q1–Q6 确认记录（已完成）、登录 ADR、合法单本下载证据、工具链版本表、存储/后台方案 | 无桌面依赖；允许的授权路线可获取有效下载权限；失败则停扩大开发 |

## 3. 自动化测试分层

### 3.1 JVM 单元测试

DTO、URL 解析与白名单、分类/排序/搜索、ID 去重、任务状态转换、批次统计、文件名清理、页码映射。不能只断言代码里出现过某个事件字符串。

### 3.2 HTTP 与文件集成测试

MockWebServer/本地受控服务构造 200/206/401/403/404/416/429/5xx、未知长度、截断、慢响应、中途断连、重定向和不同 ETag。使用自制合法 PDF 和可控大字节文件，避免 CI 请求真实受保护 CDN。

### 3.3 Android instrumented 测试

Room 迁移、ContentResolver、FileProvider、MediaStore/SAF、PdfRenderer、Keystore 异常路径、Compose 语义/导航/状态恢复。模拟器不能替代所有厂商后台实测。

### 3.4 人工端到端

受授权测试账号登录、验证码/SSO、真实合法样本下载、系统 PDF 打开、通知权限拒绝、锁屏、厂商省电行为。记录设备/系统/App/WebView 版本，不将 token 或用户信息录进公开视频。

## 5. 真机与性能矩阵

最低覆盖 API26、API28/29 存储分界、API30 目录限制、API33 通知、API34 用户发起传输、API35/36 后台规则；按最终 targetSdk 增加当期稳定版本。可以用模拟器覆盖基础兼容，但至少使用两家厂商真机验证后台与通知。

| 维度 | 场景 |
|---|---|
| 屏幕 | 360dp 级小屏、常见中屏、横屏、平板/折叠态可用性 |
| 显示 | 晨光/夜读、字体 1.0/1.3/2.0、系统减少动画/省电 |
| 网络 | Wi-Fi、移动网络、断网恢复、弱网、网络切换、限流 |
| 文件 | 小 PDF、500MB 自建文件、未知长度、损坏、加密、同标题 |
| 权限 | 通知允/拒、SAF 撤销、provider 暂不可用、存储不足 |
| 生命周期 | 旋转、后台/锁屏、普通进程死亡、强停后重新打开、系统停止任务 |
| 升级 | 老 schema → 新 schema、release 覆盖安装、Keystore 不可用 |

性能测量至少记录：设备/系统、启动至本地书架可交互耗时、目录筛选耗时、滚动卡顿、3 路下载 RSS、封面渲染 RSS 与峰值、后台耗电、下载/校验耗时。下载缓冲不随文件增长是必需；是否满足启动 ≤2 秒等目标以 M0 冻结设备和 M4 报告为准，不用开发电脑结果替代真机。

## 6. 构建、CI 与发布操作

### 6.1 环境准备（后续）

1. 安装经确认版本的 Android Studio/Android SDK、平台工具、模拟器镜像和对应 JDK。
2. 用仓库提交的 Gradle Wrapper，不依赖机器全局 Gradle。锁定依赖和 SDK，配置本地 SDK 路径但不提交个人路径。
3. 首次构建需要联网取依赖；如受网络限制，用合规缓存/镜像并记录来源，不提交下载的账号凭据。
4. 无真实上游账号也能跑 JVM/大部分 instrumentation 测试。

**仅当未来安卓工程已创建后**，从该工程根目录执行的典型命令：

```powershell
.\gradlew.bat --version
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
.\gradlew.bat connectedDebugAndroidTest
.\gradlew.bat assembleRelease
# 如商店需要 AAB，再使用 bundleRelease
```

这些命令本轮没有执行。任务名随最终模块/variant 校准，不把“不存在的工程命令”当当前项目可用操作。

### 6.2 CI 质量门

- PR：JVM 测试、Lint、debug 构建、敏感信息检查、依赖与许可证检查。
- 主干/定时：关键 API 模拟器 instrumented 测试、Room migration、UI 截图差异。
- 发布标签：干净工作树、固定工具链、release 编译、签名校验、SHA-256 校验值、版本与提交记录。
- Release keystore/password 从受控机密系统注入，不放 Git；维护恢复与备份流程。
- release 关闭调试/网络正文日志/WebView 远程调试；验证 shrink/minify 后反射/序列化/PDF 功能。
- versionCode 单调增长；versionName 按版本策略；签名更换需单独规划，不在升级时临时换 key。
- APK 先走内测与受控分发，AAB/商店权限申报仅在渠道确认后做；商店 target SDK/数据安全披露按发布当日官方规则核验。

## 7. 风险登记与降级原则

| 风险 | 级别 | 缓解与决策门 |
|---|---|---|
| 官方授权不开放/嵌入页不允许 | 阻断 | M0 首验；不绕过、不假装 Custom Tabs 可读 localStorage |
| SSO/验证码/WebView 兼容变化 | 高 | 记录版本、域名与失败路径；明确平台兼容支持范围 |
| API 非稳定对外契约 | 高 | 去敏 fixtures、显式 DTO、协议变化错误；不静默返回空目录 |
| Android 后台规则与厂商省电 | 高 | 系统适配层 + 持久任务 + 多机验证，不承诺无限后台 |
| Range/源身份不可靠 | 高 | 不满足条件从头；完整性优先于表面续传 |
| 文件/数据库提交中断 | 高 | Committing 恢复协议与杀进程测试 |
| PDF 编辑库许可/体积/内存 | 中高 | 书签单独 ADR；不让可选编辑阻塞原始 PDF 可用 |
| 版权/条款/公开分发 | 高 | 个人权限访问，不镜像教材，发布前合规核对 |
| 存储模式与用户预期不同 | 中 | Q4 已确认；首次下载说明内部教材随卸载删除，导出副本独立保留 |
| 视觉字体/动效跨平台差异 | 中 | token/图形复用，真机评审，低性能降级 |
