# 应用内更新机制设计

> 目标：让已安装的 TextbookGo-Mobile 能发现新版本、看到更新说明，并安全地完成升级。
> 边界：只做“检查 + 引导安装”，不做静默安装；不通过更新通道分发教材或账号信息。

## 1. 结论

首版采用 **Gitee 仓库内的更新清单 + 系统安装器**，不引入 FCM / 极光等推送 SDK。已实现并验证。

理由：

- 应用是自用/小范围内测，更新频率低，每天检查一次足够；
- FCM 依赖 Google 服务，国内设备基本不可用；极光/友盟会引入额外 SDK、隐私申报和常驻推送通道，收益与成本不匹配；
- Gitee 国内可直连，APK 放 Release 附件、清单放仓库文件，不依赖自建后端；
- 真正的“推送”只解决“提醒”，安装仍要经过系统包安装器，轮询已经能覆盖 99% 的场景。

如果以后确实需要“服务器主动推一条通知”，再增加 FCM/极光只负责发提醒，APK 仍然从 Gitee 下载，客户端流程不变。

> 当前发布仓库：<https://gitee.com/yizhixixi/TextbookGo-Mobile>

## 2. 更新清单

固定地址使用 Gitee contents API（**不要用 raw，raw 有 CDN 缓存**）：

```text
https://gitee.com/api/v5/repos/yizhixixi/TextbookGo-Mobile/contents/update/latest.json
```

文件本体是下面的 JSON（API 会包一层 base64，客户端已做解包）：

```json
{
  "versionCode": 12,
  "versionName": "0.2.0",
  "minSupportedVersionCode": 8,
  "apkUrl": "https://<你的域名>/textbookgo/TextbookGo-Mobile-0.2.0.apk",
  "sha256": "9f2c...e1",
  "size": 8123456,
  "publishedAt": "2026-11-01T10:00:00+08:00",
  "changelog": "1. 修复切换学科后版本记忆\n2. 新增 2022 年教材标签\n3. 下载任务移到书架"
}
```

字段约束：

| 字段 | 必填 | 说明 |
|---|---|---|
| `versionCode` | 是 | 整数，必须与 APK 的 `versionCode` 一致，比较时只用它 |
| `versionName` | 是 | 展示用，如 `0.2.0` |
| `minSupportedVersionCode` | 否 | 低于此版本强制更新；缺省等于 `versionCode` |
| `apkUrl` | 是 | 必须是 HTTPS，且与清单同域或命中白名单 |
| `sha256` | 否 | 下载后校验；强烈建议填写 |
| `size` | 否 | 展示下载大小 |
| `publishedAt` | 否 | 展示发布时间 |
| `changelog` | 否 | 纯文本，最多 2000 字 |

清单本身限制：响应 ≤ 64 KiB，超时 10 秒；解析失败按“检查失败”处理，不打扰用户。

## 3. 客户端流程

```text
启动 / 手动点“检查更新”
        │
        ├─ 距上次检查 < 24h 且非手动 → 直接跳过
        │
        ▼
GET latest.json（HTTPS、10s 超时、64KiB 上限）
        │
        ├─ 失败 → 静默（手动检查时 toast 失败原因）
        │
        ▼
manifest.versionCode <= 当前 versionCode → 已是最新
        │
        ▼
有新版本 → 弹窗：版本号、大小、更新说明
        │
        ├─ “稍后” → 记录跳过的 versionCode，本次启动不再打扰
        ├─ “更新” → 打开 apkUrl
        │        ├─ 方案 A（首版）：交给浏览器/系统下载器
        │        └─ 方案 B（可选）：App 内 DownloadManager 下载并校验 sha256
        ▼
系统包安装器校验签名并安装
（签名不一致会直接拒绝，这是最后一道防线）
```

细节：

- **启动检查**：首帧渲染后延迟 3 秒异步执行，不阻塞目录加载；失败不弹错误。
- **节流**：`lastCheckAt` 存 DataStore，默认 24 小时；设置页“检查更新”无视节流。
- **强制更新**：当前 `versionCode < minSupportedVersionCode` 时弹窗不可取消，只保留“前往更新”。
- **跳过版本**：记录 `skippedVersionCode`，同版本不再自动提示，手动检查仍提示。
- **下载安装**：首版不申请 `REQUEST_INSTALL_PACKAGES`，用浏览器打开 APK 地址，由系统下载器与安装器处理；后续若做 App 内下载，需要该权限并引导用户授权“安装未知应用”。
- **不静默安装**：Android 8+ 对自更新有系统限制，静默安装需要 root/设备管理权限，不适合本应用。

## 4. 安全约束

- 只允许 HTTPS；清单地址与 `apkUrl` 域名必须命中白名单（Gitee）。
- APK 必须继续使用**同一签名证书**；换签名会导致覆盖安装失败并丢失数据。
- 清单里的 `sha256`/`size` 目前只做展示；APK 由浏览器下载，后续若改为 App 内下载再强制校验。
- 清单只作为“版本元数据”，不执行其中的任何代码或命令。
- 不在清单里放账号、教材地址、平台 token。

## 5. 发布流程

1. 修改 `versionCode`（每次发布必须递增）与 `versionName`。
2. 用固定 keystore 构建 release APK 并签名；保存 keystore 与口令，丢失后将无法覆盖升级。
3. 生成 `sha256`，上传 APK 到 Gitee Release 附件。
4. 更新 `update/latest.json`（先传 APK，再改清单，避免用户拿到 404）。
5. 真机验证：旧版本收到提示 → 浏览器下载 → 安装 → 数据与登录状态保留。
