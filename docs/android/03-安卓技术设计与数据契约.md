## 1. 路线决策

| 路线 | 优点 | 主要代价 | 判断 |
|---|---|---|---|
| Kotlin + Jetpack Compose 原生重写 | 安卓导航、生命周期、通知、存储集成自然，无本地服务 | Go/JS 业务须重写，登录重新验证 | **已确认 Q1** |

架构不增加教材中转服务器，不收集账号，不在 APK 内分发上游 PDF。若平台不允许当前授权方案，不通过代理、隐藏接口或风控绕过弥补，应停在可行性门槛并调整范围。

### 2.2 技术选型

| 层 | 推荐 | 决策说明 |
|---|---|---|
| 语言/UI | Kotlin、Compose、Material 3 基础组件 | 自定义品牌 token，不启用默认动态配色 |
| 状态 | ViewModel + Coroutines + StateFlow | 单向数据流，UI 不持有下载连接 |
| 导航 | AndroidX Navigation 的稳定 Compose 路线 | 支持状态保存、深链、预测返回；不要混用实验接口 |
| HTTP/JSON | OkHttp + kotlinx.serialization | 显式 DTO；忽略未知字段，不放松关键字段校验 |
| 持久化 | Room + DataStore | 任务/书架/目录用 Room；偏好 DataStore |
| 凭据 | Android Keystore 加密后的私有存储 | 不把明文 token 放普通 DataStore/Room |
| 图片 | Coil（兼容 Compose 的稳定版） | 独立无凭据图片 client、缓存大小限制 |
| PDF 首页 | Android PdfRenderer | 文件描述符输入；不支持编辑 PDF/写书签 |
| 后台 | BackgroundTransferAdapter 抽象 | 按 SDK/目标策略选择，见 §6 |
| 依赖注入 | 构造注入；Hilt 可选 | 首版不为 DI 框架增复杂度 |
| 测试 | JUnit、MockWebServer、Room/Compose instrumentation | 使用自建 PDF 与去敏 fixtures |

**版本策略**：不是直接用全局 Gradle 或 `latest`。M0 记录 Android Studio、JDK、AGP、Gradle Wrapper、Kotlin、Compose BOM、AndroidX、SDK 的一组实际兼容版本，锁定版本和依赖校验信息。JDK 21 已安装不等于所选 AGP 必须用 21；按照 AGP 的兼容矩阵确定工具链。当前未核验 2026 最新稳定组合，本文不虚构固定“最新版”版本号。

## 3. 分层与调用契约

```text
Compose Screen → ViewModel → UseCases → Repositories
                                      ├─ Room / DataStore / SessionStore
                                      ├─ UpstreamApi / AuthProvider
                                      ├─ DownloadEngine / FileStore
                                      └─ CoverRenderer / PdfOutlineWriter（可选）
BackgroundTransferAdapter → 同一 DownloadEngine + Room
```

关键原则：

- **数据库是下载事实源**。UI、后台通知、任务详情订阅同一任务数据；不能由 UI 事件流是否连接决定任务存活。
- StateFlow 承载即时内存快照，不充当进程死亡后的存储。
- 网络 DTO、领域模型、Room Entity 分开，避免上游字段变化直接传到 UI。
- Domain 不依赖 Activity/Composable；文件访问不散落在页面。
- 所有密钥、授权 token 只经 SessionStore 提供，不进入 UiState、SavedStateHandle、Intent extras 或数据库任务行。

建议领域接口（说明性骨架，不是本轮已实现代码）：

```kotlin
interface AuthRepository {
    val session: StateFlow<SessionState>
    suspend fun validateSession(): AuthResult
    suspend fun setRememberSession(enabled: Boolean)
    suspend fun logout()
}
interface CatalogRepository {
    fun observeBooks(filter: CatalogFilter): Flow<List<Book>>
    suspend fun refresh(): CatalogRefreshResult
}
interface DownloadRepository {
    fun observeTasks(batchId: String? = null): Flow<List<DownloadTask>>
    suspend fun enqueue(uniqueBookIds: Set<String>): EnqueueResult
    suspend fun cancel(taskId: String)
    suspend fun pause(taskId: String)
    suspend fun resume(taskId: String)
    suspend fun retry(taskId: String)
}
interface ShelfRepository {
    fun observeShelf(): Flow<List<ShelfBook>>
    suspend fun delete(bookId: String): DeleteResult
    suspend fun reconcile(): ReconcileResult
}
```

交互式授权必须通过可见 Activity 的 AuthCoordinator 发起，由 UI 承接平台流程，再将结果交 Repository；Worker/Service 不持 Activity 引用，也不在后台强行打开登录页面。

## 4. 登录：必须先通过的验证门槛

### 4.1 不能直接迁移的部分

旧代码读 Chrome localStorage，不是可由 App 无条件调用的开放授权 API。Android 的 Custom Tabs/Auth Tab 虽然适合授权 UX，但只有平台提供受支持的 redirect/callback，App 才能得到授权结果；**它们不会将浏览器 localStorage 暴露给 App**。旧 `ND_UC_AUTH` 结构是观察到的网页存储格式，不是稳定对外契约。

### 4.2 按优先级验证

**A. 官方支持的授权接入（优先）**

核实平台有无开放授权、客户端注册资格、受支持的回调 URI/App Links、授权范围和下载权限。如有，使用系统浏览器授权与安全回调，遵循平台规范；只有平台支持时才引入 OAuth/PKCE/state，不凭空发明 token/refresh endpoint。

**B. 获允许的嵌入式官方页面（受控 PoC）**

仅在平台服务条款允许、实际页面兼容且你接受安全取舍时评估 WebView：

1. 检查所有导航的 scheme/host，仅允许核验过的授权与教材站点，SSO 域名单独记录；禁止 `file/content/javascript` 外部导航。
2. 仅可信源启用授权页面必需的 JS/DOM storage；禁止混合内容、文件访问、生产远程调试；证书错误直接终止。
3. 若需要读取网页授权数据，只有经明确批准的可信来源上才运行最小提取逻辑；不暴露通用 JS bridge，不对任意跳转页面执行凭据脚本。
4. 实测短信/验证码/人机校验、跨域 SSO、返回、过期、用户取消；不能承诺这些一定可用，也不能绕过平台限制。
5. 明确“关闭记住”时 Cookie/WebStorage 与凭据持久化的清理策略。Cookie/session 的清理必须通过对应存储 API 完成，不是假定删掉 token 即完成退出。
6. 普通 WebView 默认存在磁盘会话痕迹。若无法提供经验证的临时/隔离会话，就要清楚告知其局限，并把“进程被杀后仍无授权残留”的严格隐私要求标为未通过；需要正式浏览器临时授权或其他获支持的隔离方案，不能仅靠 `onDestroy` 清理来保证。

**C. A/B 都不通过**

交付失败证据和可行替代范围，如只打开官方页面、只做本地教材管理；不得宣称原目标已实现，不默认追加自建代理服务器或要求用户复制秘密凭据。

### 4.3 会话状态与并发失效

状态建议：`SignedOut → Authorizing → CredentialPresent → Validating → Validated`；失败到 `Expired/ValidationFailed`。没有 token 真实有效期字段时，不推测过期日期；由受保护请求确认。

- `remember=true`：Keystore 包装的加密凭据；排除系统备份，设备密钥不可用则重新授权。
- `remember=false`：App 自身凭据仅在内存；删已有持久 token，并确保后续授权不会又落盘。嵌入网页会话残留另按 §4.2 验证。
- 不记住的模式下后台任务可能在进程死亡后需要重新授权；不能同时承诺“不持久化凭据”和“被杀后可无条件继续受保护下载”。
- 401 触发 single-flight 失效处理：多个任务进入 `NeedsAuth`，最多一个前台授权入口；授权成功后重放，每个请求最多一次即时重放。
- 403 不当作刷新提示；429 遵从 Retry-After；用户取消登录不循环再次弹起。
- 退出登录清内存/持久凭据及批准范围的 Web 会话；已下载文件保留。活动受保护网络连接取消，任务进入 NeedsAuth/用户取消，不能继续隐式持有旧 token。
- Header 只附到经核验需鉴权的精确主机；每个重定向再次检查，不靠字符串包含判断可信域。

M0 输出：授权路线 ADR、允许域名列表、设备/WebView 版本、成功/取消/过期证据、资源预检结果、可公开去敏 fixtures。不在报告里保留账户秘密。

## 5. 数据模型与目录同步

### 5.1 核心表（建议）

| 表 | 关键字段 | 约束 |
|---|---|---|
| `catalog_generation` | id, upstreamVersion, fetchedAt, status, expectedShardCount, loadedShardCount | 完整版本才激活 |
| `catalog_book` | generationId, bookId, title, coverUrl, version, volume | generationId + bookId 唯一 |
| `book_tag` | generationId, bookId, dimensionId, tagId, tagName | 支持一本书多个年级/学科，不能压成单字符串 |
| `download_batch` | batchId, createdAt, state | 统计由任务聚合 |
| `download_task` | taskId, bookId, titleSnapshot, state, downloadedBytes, totalBytes?, tempPath, storageMode, targetUri?, etag?, lastModified?, expectedSize?, expectedMd5?, attempts, errorCode?, createdAt, updatedAt | downloadedBytes≥0，状态显式；不保存 token |
| `batch_task` | batchId, taskId | 同一本活动任务可供后续批次复用，避免两路写同文件 |
| `shelf_book` | bookId, title, filename, storageMode, localPath?/contentUri?, size, checksum?, downloadedAt, availability | bookId 唯一，标注可访问/缺失/待授权 |
| `export_record`（可选） | bookId, exportUri, exportedAt | 导出副本不等于主文件，删除范围明确 |

只有单个批次队列时可简化 `batch_task`，但要明确禁止第二批次并发入队；不能因为 UI 一次只显示一面板，就允许后台重复下载同 ID。

数据库 schema 导出纳入版本管理，迁移测试覆盖升级；时间内部用 UTC epoch，展示按设备时区。实体不保存原始账号信息或带凭据的 URL。资源链接可能过期，重试/重启时重新请求详情解析，不把旧 URL 当永久地址。

### 5.2 DTO 与解析样例

下面为**人工构造**样例，不是实际在线响应：

```json
{
  "module": "tch_material",
  "module_version": 1,
  "urls": "https://s-file-1.ykt.cbern.com.cn/example/a.json,https://s-file-2.ykt.cbern.com.cn/example/b.json"
}
```

按逗号拆分、trim、过滤空值；JSON 允许未知字段，关键字段类型不匹配则报告协议变化。详情 `ti_items` 用字段名映射处理 `ti_is_source_file/ti_file_flag/ti_storage/ti_storages/ti_format/ti_size/ti_md5`，字节计数全部 Long。

### 5.3 目录更新算法

1. 请求版本 → 校验分片 URL（HTTPS、可信主机、合理数量/响应大小）。
2. 最多 5 路拉分片，独立记录结果；可中止、有限退避。
3. 解析并按 bookId 去重，保留多标签；冲突字段使用确定性策略并记录去敏诊断。
4. 写 staging generation；全部应有分片成功后，Room 事务切 active generation。
5. 任何分片失败保留上一完整版本，显示更新不完整；无旧版本可提供明确标注的部分目录，但默认不将其作为完整缓存。
6. 标准年级固定顺序；未知年级追加后按稳定字符串顺序，学科保持现有字符串排序。按标签名 contains 是现有兼容规则；未来改 tagId 精确匹配需独立评审/样例回归。
7. 书名 trim+case-insensitive 子串匹配限当前分类；SQLite LIKE 的 `%/_` 必须转义，否则用户输入会变通配符并偏离现有语义。
8. 展示已下载态通过 shelf 可访问文件状态关联；不只凭历史 ID。

## 6. 下载引擎、调度与状态机

### 6.1 状态

```text
Queued → Resolving → Downloading → Verifying → Committing → Succeeded
             │           │            │          │
             ├───────────┴────────────┴──────────┤
             ▼                                   ▼
      NeedsAuth / WaitingNetwork / WaitingStorage / RetryWaiting / Failed

任一非终态 → CancelRequested → Cancelled
已存在可用教材 → Skipped
用户暂停：Queued / Resolving / Downloading → PauseRequested → Paused
用户继续：Paused → Queued（重新验证资源后续传或从头）
```

- 每个任务必须最终处于 Succeeded/Skipped/Failed/Cancelled，或明确的可恢复等待态；批次不以“流关闭”代表全部成功。
- `Succeeded` 只在文件与数据库提交完成后设置。可选书签独立为 `NotRequested/Pending/Applied/Unavailable/Failed`，不覆盖基础下载终态。
- Queued/Resolving/Verifying 不显示虚构下载百分比；总长度为未知时 `totalBytes=null`。
- 调度有全局 3 路上限，而不是每个 Worker 都开 3 路造成无界并发。
- 每 bookId 以数据库任务认领+唯一约束/事务互斥，跨 UI/Worker/Service 不仅靠一个进程内 Set。
- 数据库存进度建议每 500ms 或传输增量阈值一次，UI 可 100–250ms 更新，通知约 1 秒更新；退出/暂停/失败必须立即持久化，不每 32KB 写一次 Room。

### 6.2 后台承载选择

后台实现独立为 `BackgroundTransferAdapter`，不把下载绑定 ViewModel scope。**以下策略须在冻结 targetSdk 时按官方文档与设备实测更新，不能保证无限后台执行。**

- API 26–33：用户在前台点击启动的持久任务，可使用带前台通知的 WorkManager 任务/受控 dataSync 前台服务；二者选择一种主要承载，避免同一任务被双调度。
- API 34+：评估用户发起数据传输 Job（UIDT），其适用前提、启动时机、通知和权限均需符合平台要求；不合适时用经验证的前台传输路线。
- target API 35+ 要验证 dataSync 前台服务累计运行时限、超时回调和后台启动限制，不能靠重启 Service 绕过配额。
- API 36+ 要验证长运行 WorkManager 与 JobScheduler 配额的关系；若长 Worker 不适合本项目，使用满足约束的用户发起传输/直接前台服务，而不是只加 `setForeground` 就承诺无限下载。
- 重试退避、断网唤醒、进程恢复可用 WorkManager，但它不是精确计时器，受系统、电量和厂商策略限制。
- 系统“强行停止”后不承诺自动恢复；用户再次打开后核对并恢复。划掉任务卡与强停不是同一件事。
- 通知被拒绝时，前台任务仍需按平台要求提交前台通知；抽屉可见性受系统控制，不能因拒绝通知直接崩溃或偷偷运行不合规后台。

M0/M1 用大文件假服务器验证所选路线的锁屏、切后台、进程死亡、系统停止、配额耗尽和恢复；记录清晰的支持矩阵，不用“Service 永不被杀”的错误承诺。

### 6.3 文件传输流程

1. 从 Room 认领唯一任务；确认空间、目标可写、会话需求。
2. 读资源详情，按旧优先级选候选；先校验 URL scheme/host。候选非 PDF 或内容不符时报告不支持，不把任意二进制标成 PDF。
3. 主文件名建议内部使用 `{bookId}.pdf`，展示名/导出名使用 `清理标题_<短ID>.pdf`；标题不得进入任意目录路径，拒绝 `../` 等路径穿越。
4. 临时文件放与最终内部文件同一卷的专用目录，使用 32–64KiB 缓冲；支持 HTTP 取消，逐块检查取消与剩余空间。
5. 独立设置连接/读超时；下载不采用“整个文件 60 秒必须完成”的全局总超时，改用无进展超时与后台时间预算。建议起始 connect 15s/read-idle 60s，再经弱网实测调整。
6. 网络/5xx 有限重试与指数退避、jitter；示例最多 3 次尝试（含首次）；429 遵守 Retry-After，401 需授权，403/404 不盲重试。
7. 主失败按策略试备用，不能把同地址当有效故障切换。切换来源无强验证器/同内容证明时从头下载，不将新源追加旧文件。
8. 验证长度（已知时）、PDF 内容特征，并视上游有效 `ti_md5` 做完整性比较。MD5 仅表示传输一致性，不当成安全签名。解析实际 PDF 的测试与恶意输入防护另行覆盖。
9. 先完成文件提交/持久元数据，再将任务成功、书架入库；可选书签完成前不要让多个读取/编辑器同时改同一文件。

### 6.4 正确断点续传与暂停（已确认 Q5，首版必需）

- 保存已经真实落盘的字节数、ETag（优先强验证器）、Last-Modified、已知长度与资源身份。
- 有安全验证器且临时文件长度为 N 时，发 `Range: bytes=N-` 与合适 `If-Range`；正确处理编码，不能用解压后偏移拼编码流。
- 返回 **206**：必须校验 Content-Range 起始为 N、范围与总量一致，且资源验证器符合预期才追加；最终进度为 N + 本次传输字节。
- 返回 **200**：服务端忽略范围，必须 truncate 从 0 重下，不能 append。
- 返回 **416**：只有能验证临时文件已完整、长度/校验一致才视作已完成，否则删除/隔离后重下。
- ETag 变化、来源变化、缺少可证明同一资源的条件时安全从头，不强行“续传”。Accept-Ranges 不是成功续传的唯一证据。
- 暂停时取消网络，安全落盘并持久化偏移/验证器后进入 Paused、释放并发槽；Queued/Resolving 可在偏移 0 时暂停。暂停保留临时文件，取消默认清理临时文件，两者不可混淆。
- Paused 是用户意图，不因进程重建、网络恢复或后台调度而自行恢复；仅 resume 操作回到 Queued。Verifying/Committing 关键阶段不提供即时暂停，避免破坏事务。
- 恢复时重新验证资源，条件不足则清空临时内容并明确提示从头下载。首版必须在受控服务器通过真实 206 与安全降级测试；上游不支持 Range 不等于可以不实现整个续传能力。

### 6.5 文件与数据库不是一个事务

Room 事务不能覆盖磁盘 rename 或 MediaStore 提交；需要可恢复的两阶段流程：

1. 写 `Committing` 以及预期最终位置/校验结果。
2. 内部文件 close/flush（必要时 sync），同卷 rename；不得先删除其他 ID 的同名文件。
3. Room 事务 upsert shelf + 设置 Succeeded；若入库失败，保留可核对文件与 Committing，不虚报成功。
4. 启动核对：Committing 有完整最终文件则补入库；只有完整临时文件则继续提交；无文件则回可重试态。
5. 外部目标可能不支持原子 rename：采用内部完整 staging → 输出目标 → 验证 → 最后发布可见。MediaStore 用 pending 状态；SAF 用临时/不完整标记与恢复记录，provider 行为需测。
6. 删除同样先记删除意图，再删真实目标，再删书架/缓存；无权限则保留错误状态而非直接删记录。已导出副本不自动连带删除。

## 7. 文件保存、打开、分享与删除

### 7.1 已确认 App 内保存＋按需导出

已确认采用 A 模式（Q4），首版不开发主存储切换或自动写公共 Downloads。B 只保留为未来方案对照，不是双模式交付承诺。

| 项目 | A：App 内保存 + 导出（已确认） | B：自动保存系统 Downloads（后续备选） |
|---|---|---|
| 内部主文件 | App 专用持久文件目录，不放 cacheDir | 内部 staging 完整后提交系统目标 |
| 用户感受 | 书架即入口，导出后文件才外部可见 | 完成后文件管理器可见，接近桌面目录习惯 |
| 卸载 | App 私有教材随卸载删除，必须提示 | 公共文件一般保留，具体 provider/所有权需验证 |
| 权限 | 基础下载无需存储运行时权限 | API29+ 用 MediaStore.Downloads；老系统需 SAF 或单独兼容策略 |
| 打开/分享 | FileProvider/content URI、临时只读授权 | content URI、系统权限模型 |
| 删除 | 删主文件与书架；导出副本保留 | 删公共原文件可能需用户确认/授权，不伪造成功 |

A 模式的专用目录可以选内部 filesDir 或 app-specific external，M0 记录容量/可用性策略。不可把下载目录放可被系统随时清除的普通缓存；设置页展示内部文件对卸载的行为。

B 模式：API29+ 将完整文件作为 `application/pdf` 写入 Downloads 对应 MediaStore，使用 `IS_PENDING` 控制最终可见性；实际路径只是展示，不持久存猜测的 `/sdcard/...`。API26–28 默认通过 SAF 由用户授权位置，不直接为“方便”索取全盘权限。

**不默认请求 MANAGE_EXTERNAL_STORAGE。** Android 11+ 的目录树选择有系统限制，包括不能简单让用户授予整个 Downloads 根目录；不能把 `ACTION_OPEN_DOCUMENT_TREE` 当作万能下载目录选择器。

### 7.2 导出与 URI

- 单本导出：`ACTION_CREATE_DOCUMENT`，用户指定位置，复制流，支持取消和失败清理。
- 批量导出/自选目录：如确有需求，用 SAF tree + `takePersistableUriPermission`，保存 URI；被撤销/重装/文档移动时重新授权。
- URI 不等于文件路径，不用 `File(uri.path)`；通过 ContentResolver 的流/描述符访问。
- 打开使用 `ACTION_VIEW`、MIME `application/pdf`、`FLAG_GRANT_READ_URI_PERMISSION`；分享使用系统 Sharesheet 与 content URI，绝不暴露 `file://`。
- 不保证每台手机都有能定位特定文件夹的文件管理器。提供“打开教材 / 导出 / 查看保存位置”回退；不将“打开目录”做成仅硬编码某厂商 Intent。
- 外部文件失联：区分明确不存在、授权失效、云 provider 离线与读取错误；只有确认缺失或用户操作才移除记录。

### 7.3 封面与 PDF 书签

**封面：**选书优先已知平台缩略图，已下载可用 PdfRenderer 的首页；失败显示原拼贴。书架推荐优先本地首页，在线缩略图只作可选回退。对文件描述符渲染目标尺寸（如 300–450px 宽），后台串行/受限并发，及时 close page/renderer/PFD，不 `readBytes()` 整本 PDF。

缓存以 bookId + 文件校验/修改版本为 key，限制内存 LRU 与磁盘缓存（起始建议 64MB，性能评审调整）；删除/重新下载清理旧缓存。拼贴不需要网络与额外权限。

**PDF 目录书签（P1，可选，已确认 Q6）：**旧流程是详情 → ebook_mapping → ebook_id / node-page mappings → tree → 嵌套书签。PdfRenderer 只渲染，不会写 PDF outline；不能以“已经能展示 PDF”声称完成目录写入。

首版不要求实现此功能，也不为它引入 PDF 写入依赖；后续确认启用时先做库 ADR：Android 兼容性、维护、许可证、体积、超大文件内存、加密/损坏文件和页码映射。写入采用新副本后验证与原子替换，失败保留原 PDF；不要求手机装外部 pdfcpu，也不带 Windows DLL。未支持/无映射/写入失败分别记录，页码基准用真实样例确认。

## 8. 权限、安全与隐私

| 能力 | 原则 |
|---|---|
| INTERNET / 网络状态 | 按实际请求声明；不申请通讯录、定位等无关权限 |
| 前台任务 | 声明所选前台服务类型和目标 SDK 所需权限；UIDT 按适用要求声明与核验 |
| 通知 | API33+ 在用户启动下载的合理时机请求 POST_NOTIFICATIONS，说明作用并处理拒绝 |
| 存储 | 私有目录无需全盘权限；公共文件走 MediaStore/SAF，老系统单独定义策略 |
| 安装更新 | 首版不做静默自更新，不默认请求安装未知应用权限 |

安全清单：

1. HTTPS、系统证书验证，不接受所有证书，不加通用忽略 SSL 开关。
2. 版本/目录/备用/封面所有外部 URL 校验；下载私有凭据只发可信鉴权主机；重定向每跳复核。
3. OkHttp 日志过滤 Header、Cookie、查询参数；release 不启用正文日志、WebView 调试与敏感截图输出。
4. Keystore 密钥异常、备份还原后无法解密时安全清空并重新登录，不崩溃、不尝试明文回退。
5. 备份规则排除凭据、临时文件、数据库中敏感字段和大体积教材；按产品决定设置/非敏感元数据是否备份。
6. 不把验证码/密码经 JS bridge 上报；不上传教材/账号到自建服务；没有遥测需求就不默认集成分析 SDK。
7. 下载内容、封面和 PDF 解析都视为不可信输入：响应大小上限、文件名清理、磁盘配额、取消与清理、库安全更新。
8. 关于页保留原 MIT 作者/许可；教材版权与平台访问条款不因代码 MIT 就获得再分发授权。

## 9. 错误域与观测

统一错误码建议：`NetworkUnavailable/Timeout/AuthRequired/Forbidden/RateLimited/CatalogIncomplete/SchemaChanged/NoPdfResource/StorageFull/PermissionLost/FileMissing/IntegrityMismatch/PdfUnsupported/Cancelled/Unknown`。

任务至少保存错误码、去敏用户提示、重试次数、最后状态时间；开发日志带 taskId/batchId/httpStatus/阶段耗时/字节数量，不带凭据或账号。支持导出**去敏诊断**为后续建议，首版至少能在 debug 查看状态流。

批次统计从终态推导而非依赖脆弱的事件计数器；书签失败是警告，不计为 PDF 下载失败；UI 显示层不吞掉 Repository 错误。
